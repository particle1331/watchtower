01. Overview & the golden path

The four planes, the fixed invariants, the golden path a model travels, and the phased plan the course follows.

02. Platform foundation

Phase 0 — the Azure footprint every later phase depends on: registry, ACA environment, Postgres, storage, Key Vault, Grafana, per-workload identities, and self-hosted MLflow.

03. Reproducible training & registry

Phase 1 — training and evaluation as ACA Jobs that log to self-hosted MLflow with reconstructable lineage and a results-DB record.

04. Results DB & batch workflows

Phase 2 — the generic results database, scheduled and manual triggers, and batch fan-out with parent/child rows and a stateless continuation rule.

05. Online serving & promotion

Phase 3 — optional online HTTP serving as an ACA App that loads an exact model version, with promotion and rollback as version/definition changes.

06. Observability & dashboard

Phase 4 — three non-overlapping observability layers plus a lightweight catalog/launcher dashboard over the four planes.

07. LLM release artifacts

Phase 5 — package an LLM app as an MLflow pyfunc version, evaluate it with a repeatable job, and release it through the same promotion path as any model.

08. Multi-GPU training (exception track)

The admission-gated exception: distributed / multi-GPU training on Azure ML command jobs against min-zero clusters, logging to the same self-hosted MLflow.

09. Broker upgrade (only if forced)

The conditional upgrade path: Celery-as-a-library on short-lived KEDA-triggered ACA Jobs backed by managed Redis — adopted only when batch fan-out outgrows the results-DB continuation rule.

10. End-to-end integration

Walk the whole golden path on the deployed platform, verify the acceptance evidence for each phase, and catalog every deferred production extension.
